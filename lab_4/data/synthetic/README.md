# Паспорт синтетического корпуса

## Назначение и происхождение

Корпус предназначен для учебного распознавания и маскирования персональных сведений в русскоязычных медицинских текстах. Все записи сформированы локальным генератором из авторских шаблонов. MIMIC, реальные медицинские записи, внешние сервисы и исходные английские словари не использованы.

Имена и организации имеют учебный характер. Телефоны содержат заведомо недействительный код `000`, почта использует домен `example.org`, идентификаторы начинаются с `0000`. Название Петрозаводска является общедоступным географическим названием; записи не описывают реальных пациентов. Возможное совпадение вымышленного имени или номера с реальным значением не подтверждает связь с человеком.

## Состав

| Выборка | С сущностями | Без сущностей | Всего | Число шаблонов |
| --- | ---: | ---: | ---: | ---: |
| train | 96 | 12 | 108 | 9 |
| validation | 24 | 12 | 36 | 3 |
| test | 24 | 12 | 36 | 3 |
| Всего | 144 | 36 | 180 | 15 |

Использованы 12 шаблонов с сущностями и 3 отрицательных. Для каждого шаблона сформировано 12 вариантов. Каждый из восьми классов содержит 72 сущности: 48 в train, 12 в validation и 12 в test. Всего размечено 576 сущностей.

Разделение выполнено по `template_id`: один шаблон представлен только в одной выборке. Начальное значение генератора — `42`. Тексты шаблонов, `seed` и `records_per_template` загружаются из `manifest.json`. Этот файл служит конфигурацией генератора. Обе группы положительных шаблонов представлены во всех выборках: клинические записи с именем, возрастом, датой и организацией; контактные записи с телефоном, почтой, идентификатором и местом.

## Формат

Каждый файл `*.jsonl` содержит по одной записи JSON на строку:

- `id` — уникальный идентификатор записи;
- `template_id` — группа шаблона;
- `split` — `train`, `validation` или `test`;
- `text` — исходный текст без нормализации после разметки;
- `entities` — список объектов с `start`, `end`, `label`, `text`;
- `tokens` — список объектов с `text`, `start`, `end`;
- `bio_tags` — BIO-метки в порядке токенов.

Интервалы `[start, end)` заданы в символах строки Python. Классы: `NAME`, `DATE`, `PHONE`, `EMAIL`, `ID`, `LOCATION`, `ORGANIZATION`, `AGE`. Схема границ описана в `reports/lab04-report.md` относительно корня лабораторной.

Токены выделены выражением `\w+|[^\w\s]`: последовательности букв и цифр образуют слова, пунктуация выделяется отдельно. Пробелы и переносы остаются в исходном тексте и учитываются в позициях. Это исходная токенизация для BIO, а не токенизатор BERT.

Вариативность включает инициалы, дефисные фамилии, дательный падеж, переносы внутри имени, три формата даты и несколько форматов телефона. Отрицательные записи содержат клинические термины, дозировки, температуру, длительность симптомов и другие числа без персональных сведений.

## Воспроизведение и проверки

Команды выполняются из корня `lab_4`, генератор и валидатор используют Python и стандартную библиотеку. Для тестов дополнительно требуется совместимая с установленным Python версия pytest:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 src/generate_data.py
PYTHONDONTWRITEBYTECODE=1 python3 src/data_checks.py
PYTHONDONTWRITEBYTECODE=1 python3 -m pytest -q -p no:cacheprovider test
```

Генератор читает `manifest.json` и перезаписывает только `train.jsonl`, `validation.jsonl` и `test.jsonl`. Конфигурационный файл при генерации не изменяется. Для изменения корпуса редактируются `seed`, `records_per_template` или шаблоны в манифесте, после чего выполняются команды генерации, валидации и тестов. Ручное редактирование JSONL нарушает воспроизводимость.

Идентификаторы шаблонов имеют вид `clinical_...`, `contact_...`, `negative_...`; каждая группа содержит минимум три шаблона. После перемешивания группы по одному шаблону выделено в validation и test, остальные относятся к train. Положительные шаблоны используют поля восьми классов, отрицательные — `days`, `temperature`, `dose`, `pulse`, `value`, `breathing`, `percent`. Форматирование и преобразования полей не поддерживаются. Для `clinical_03` в генераторе задан дательный падеж имени.

Манифест проверяется до записи файлов: типы параметров, положительное число записей, группы и поля шаблонов. Минимальные количества записей и сущностей проверяются по сформированному корпусу. Таблицы паспорта и отчёта описывают конфигурацию `seed=42`, `records_per_template=12` и требуют актуализации при изменении корпуса.

Проверки охватывают диапазоны и подстроки, отсутствие пересечений, токены и восстановление сущностей из BIO, уникальность текстов и идентификаторов, разделение шаблонов и минимальные количества примеров. Тесты в `test/test_data.py` сравнивают сохранённый корпус с результатом повторной генерации. Тесты правил и метрик расположены в `test/test_e0.py`. Отдельные контрольные примеры проверяют инициалы, дефисы, переносы, повтор имени и отрицательную запись; намеренно повреждённая разметка отклоняется.

## Ограничения

Корпус небольшой и шаблонный. В нём присутствуют искусственные признаки: недействительный код телефона, домен почты и префикс идентификатора. Положительные шаблоны имеют фиксированные сочетания четырёх классов. Доля отрицательных примеров различается между выборками. Эти особенности могут упрощать задачу и влиять на метрики; результат не переносится автоматически на реальные медицинские тексты. Пересечение словарных значений между выборками допускается; разделение контролируется по шаблонам, а не по пациентам или отдельным значениям сущностей.

Записи хранятся локально как учебные артефакты. Корпус не содержит привязки к реальным пациентам и не подтверждает безопасность применения модели к реальным данным.
