# Лабораторная работа №4

## Обезличивание медицинских данных: распознавание сущностей

Цель работы — построить учебную цепочку обнаружения и маскирования персональных сведений в синтетических русскоязычных медицинских текстах и сравнить регулярные выражения, SciBERT и RuBERT.

## 1. Схема сущностей

### 1.1. Классы

Используются восемь классов. В данных и коде применяются английские обозначения из таблицы; их соответствие русским названиям едино для всех методов.

| Класс | Метка | Что размечается | Синтетический пример |
| --- | --- | --- | --- |
| Имя | `NAME` | Фамилия, имя, отчество или инициалы человека, включая формы со склонением | `Учебнову Алексею Петровичу`, `Учебнов А. П.` |
| Дата | `DATE` | Полная календарная дата в цифровом или текстовом формате | `12.03.2026`, `12 марта 2026 года` |
| Телефон | `PHONE` | Телефон целиком, включая код страны, скобки, пробелы и дефисы внутри номера | `+7 (000) 000-00-00` |
| Почта | `EMAIL` | Адрес электронной почты целиком | `patient@example.org` |
| Идентификатор | `ID` | Значение номера полиса, медицинской карты или другого идентификатора; вид документа задаётся контекстом | `0000 000000` в тексте `полис 0000 000000` |
| Место | `LOCATION` | Название города, региона или адрес; тип населённого пункта и адресные сокращения включаются в сущность | `г. Петрозаводск`, `ул. Учебная, д. 0` |
| Организация | `ORGANIZATION` | Полное название учреждения с организационным обозначением и кавычками, если они указаны | `ГБУЗ «Учебная больница»` |
| Возраст | `AGE` | Возраст человека с единицей измерения, включая составные формы | `87 лет`, `5 месяцев`, `45-летний` |

Примеры создаются для учебного корпуса и не заимствуются из реальных медицинских записей. Наличие похожего значения в реальном мире не означает, что пример описывает реального человека.

### 1.2. Правила определения границ

Основная разметка хранится на уровне символов исходного текста. Каждая сущность задаётся полями `start`, `end`, `label`. Интервал полуоткрытый: `start` включается, `end` не включается. Позиции считаются в символах строки Python, а не в байтах UTF-8; выражение `text[start:end]` должно точно возвращать размеченный фрагмент.

Пример записи:

```json
{
  "text": "Пациент Учебнов Алексей, 45 лет.",
  "entities": [
    {"start": 8, "end": 23, "label": "NAME"},
    {"start": 25, "end": 31, "label": "AGE"}
  ]
}
```

Правила разметки:

- Начальные и конечные пробелы не входят в сущность. Пробелы, дефисы и переносы строк внутри единого фрагмента сохраняются.
- Слова-подсказки `пациент`, `телефон`, `почта`, `полис`, `карта` не входят в сущность. Для идентификатора размечается только его значение.
- Пунктуация предложения не входит в сущность. Точки в инициалах, разделители даты, знаки телефона и кавычки названия организации входят, если являются частью фрагмента.
- Соседние компоненты одного имени образуют одну сущность `NAME`; раздельно упомянутые люди образуют отдельные сущности.
- Название места внутри полного названия организации отдельно не размечается: весь фрагмент получает `ORGANIZATION`. Вложенные и пересекающиеся сущности в корпусе не допускаются.
- Числа классифицируются по контексту. Дозировки, результаты анализов, температура и длительность симптомов не являются возрастом или идентификатором: например, `5 мг`, `37,2 °C`, `кашель 3 дня` остаются вне сущностей.
- Возраст размечается независимо от величины. Частичные даты и неоднозначные фрагменты без достаточного контекста исключены из принятой схемы.
- После назначения символьных позиций исходный текст не изменяется. Любая последующая нормализация требует пересчёта позиций.

### 1.3. Схема BIO

Для классификации токенов выбрана схема BIO:

- `B-TYPE` — первый токен сущности типа `TYPE`;
- `I-TYPE` — каждый следующий токен той же сущности;
- `O` — токен вне сущностей.

Для восьми классов используются 17 меток: общая `O` и пары `B-`/`I-` для `NAME`, `DATE`, `PHONE`, `EMAIL`, `ID`, `LOCATION`, `ORGANIZATION`, `AGE`.

Пример разметки на уровне слов и пунктуации:

| Токен | Метка |
| --- | --- |
| Пациент | `O` |
| Учебнов | `B-NAME` |
| Алексей | `I-NAME` |
| , | `O` |
| 45 | `B-AGE` |
| лет | `I-AGE` |
| . | `O` |

Сущность из одного токена получает `B-TYPE`. Новая сущность всегда начинается с `B-TYPE`, даже если непосредственно перед ней находится другая сущность того же класса. Метка `I-TYPE` допустима только после `B-TYPE` или `I-TYPE` того же класса.

### 1.4. Согласование с подтокенами

Для согласования меток с подтокенами BERT выбрана следующая стратегия:

1. Исходные слова получают BIO-метки по символьным диапазонам сущностей.
2. Первый подтокен слова получает исходную метку слова.
3. Последующие подтокены получают `I-TYPE`, если слово помечено `B-TYPE` или `I-TYPE`; для слова с меткой `O` сохраняется `O`.
4. Специальные токены и дополнение последовательности получают значение `-100`, исключающее их из функции потерь и оценки.
5. Соответствие слов и подтокенов определяется через `word_ids()`. Для восстановления символьных позиций сохраняются границы исходных слов и учитываются смещения подтокенов относительно этих слов.

Значение `-100` не является отдельным классом модели.

### 1.5. Условия корректности и ограничения схемы

Корректная разметка удовлетворяет следующим условиям:

- `0 <= start < end <= len(text)` для каждой сущности;
- точное совпадение `text[start:end]` с фрагментом, вставленным генератором;
- принадлежность метки одному из восьми классов;
- отсутствие пересечений диапазонов;
- совпадение числа токенов и меток и допустимость переходов BIO;
- значение `-100` у специальных токенов и дополнения после токенизации.

Клинические термины и диагнозы сами по себе не входят в принятую схему. Также она не охватывает все косвенные идентификаторы: редкие события и сочетания обстоятельств могут позволить повторную идентификацию. Успешное распознавание этих восьми классов не гарантирует полного обезличивания. Качество на синтетическом корпусе не подтверждает качество на реальных медицинских текстах.


## 2. Синтетический корпус

### 2.1. Формирование и формат

Корпус сформирован локально программой `src/generate_data.py`. Начальное значение генератора `42`, число записей на шаблон и тексты шаблонов загружены из конфигурационного файла `data/synthetic/manifest.json`. Корректность параметров и полей шаблонов проверяется до записи корпуса; манифест при генерации не изменяется. Использованы 12 шаблонов с сущностями и 3 отрицательных шаблона; для каждого получено 12 вариантов. Исходные записи MIMIC и реальные медицинские сведения не использованы.

Сущности размечены при подстановке значений в шаблон. Для каждого фрагмента сохранены тип, исходное значение и символьный диапазон `[start, end)`. Записи содержат исходный текст, идентификаторы записи и шаблона, принадлежность выборке, токены с позициями и BIO-метки. Данные сохранены в `data/synthetic/*.jsonl`, шаблоны и параметры — в `manifest.json`. Паспорт корпуса расположен в `data/synthetic/README.md`.

Для исходной токенизации применено выражение `\w+|[^\w\s]`: слова и числа выделены отдельно от пунктуации. BIO-метки получены из символьных диапазонов. Данный этап не включает токенизацию BERT или согласование специальных токенов.

В примерах представлены инициалы, дефисные фамилии, склонения, переносы строк внутри имени, цифровые и текстовые даты, различные записи телефонов. Отрицательные примеры содержат температуру, дозировки, результаты анализов и длительность симптомов. Телефоны используют недействительный код `000`, почта — домен `example.org`, идентификаторы — префикс `0000`.

Корпус проверяет учебную цепочку обработки; его метрики не подтверждают качество на реальных медицинских текстах.


## 3. E0: базовое решение на регулярных выражениях

### 3.1. Правила и запуск

Решение реализовано в `experiments/e0.py` средствами стандартной библиотеки Python. Использованы регулярные выражения для трёх классов:

- `EMAIL` — адрес с латинскими буквами, цифрами и распространёнными символами локальной части, доменным именем и буквенным доменом верхнего уровня;
- `PHONE` — номер с префиксом `+7` или `8`, трёхзначным кодом и семью цифрами номера; поддержаны скобки, пробелы, табуляция и дефисы;
- `ID` — четыре цифры и шесть цифр, разделённые пробелами или табуляцией.

Правила основаны на форматах корпуса и примерах обучающей выборки. Они не привязаны к домену `example.org`, коду телефона `000` или нулевому префиксу идентификатора. При пересечении кандидатов принят приоритет `EMAIL`, затем `PHONE`, затем `ID`; кандидат с меньшим приоритетом исключается целиком. Результат содержит `start`, `end`, `label` и упорядочен по позиции начала.

Запуск из корня лабораторной:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m experiments.e0
```

Программа выводит результаты на `validation.jsonl` в формате JSON. Результат проведённого запуска сохранён в `reports/e0-validation.json`. Тестовая выборка в данном эксперименте не использована.

### 3.2. Методика оценки

Сущность считается найденной только при точном совпадении типа, начала и конца в пределах одной записи. Ошибка границы или типа даёт одновременно ложное предсказание и пропуск эталонной сущности. Счётчики суммируются по записям, поэтому одинаковые позиции в разных текстах не объединяются.

В соответствии с пунктом 4.1 задания вычислены precision, recall и F1 только по покрываемым правилами классам `EMAIL`, `PHONE`, `ID`, а также микро- и макроусреднение по этим трём классам. При нулевом знаменателе значение метрики принято равным нулю. Макроусреднение представляет арифметическое среднее поклассовых метрик.

### 3.4. Проверки и ограничения

Контрольные примеры подтвердили распознавание форматов телефона, почты и идентификатора, исключение конечной пунктуации, отсутствие частичных совпадений внутри более длинных чисел и приоритет почты при пересечении с номером. Для вручную заданных сущностей получены ожидаемые `TP=1`, `FP=2`, `FN=2`, микро-F1 `1/3` и макро-F1 `2/9` по трём классам. Проверены ошибки границ и типа, пустая оценка, нулевые знаменатели и суммирование одинаковых сущностей в разных записях.

Правила охватывают ограниченные форматы. Они не проверяют существование телефона или почты и могут ошибочно принять число формата «четыре цифры — пробел — шесть цифр» за идентификатор. Высокие показатели связаны с шаблонным корпусом и не подтверждают качество на произвольных медицинских текстах. Результаты этого раздела относятся только к регулярным выражениям. Оценка SciBERT приведена в разделе 4.

## 7. Маскирование

Функция [`mask_entities`](../src/masking.py) принимает исходный текст и предсказанные моделью сущности в виде диапазонов `[start, end)` с метками класса. Она проверяет диапазоны и заменяет фрагменты справа налево, сохраняя текст между ними. Перекрывающиеся диапазоны объединяются целиком. Если классы совпадают, сохраняется маркер класса, а при разных классах используется `[REDACTED]`. Соседние диапазоны без перекрытия маскируются отдельно.

Команда запуска из каталога лабораторной читает предсказания RuBERT из архива и сохраняет [CSV](e1-rubert-test-masked.csv) в кодировке UTF-8. В каждой строке записаны идентификатор `id`, исходный текст `original_text` и маскированный текст `masked_text`. По умолчанию файл `<имя>-masked.csv` сохраняется рядом с входным JSONL.

```bash
unzip -p experiments/e1_rubert_results.zip test-predictions.jsonl |
  python3 -m src.masking data/synthetic/test.jsonl --output reports/e1-rubert-test-masked.csv
```

На синтетической тестовой выборке проверены 36 записей. Все 96 эталонных сущностей заменены маркерами по предсказаниям RuBERT, остальной текст сохранился.
